What this feature does

Six capabilities shipped in a single modal.

01 · ACCOUNT

Multi-account selection

Pick the exact token and identity that should own the repository. Demo accounts and live PAT sessions share one selector.

02 · OWNER

Personal or organization

Target your personal handle or any organization your token can write to. Orgs are resolved live from /user/orgs.

03 · PREVIEW

Live URL preview

github.com / owner / name updates on every keystroke, so you always see the exact destination before you create.

04 · VALIDATION

Real-time name checks

Blocks leading/trailing dots or hyphens, .git suffix, and non-alphanumeric characters before the network call even fires.

05 · VISIBILITY

Segmented private/public toggle

Private by default, with a hardware-style segmented control that mirrors the exact ZeroCommit visual language.

06 · CARRYOVER

Staged change carryover

Keep your staged buffers when you spin up a new repo. The first push lands directly into the new target instead of being purged.

Three-step pipeline

From click to live repo in one flow.

1

Authenticate

Resolve the active PAT or OAuth account from the vault (or the live PAT field in this showcase) and probe /user + /user/orgs.

2

Create

POST /user/repos or /orgs/{org}/repos with auto_init: true so the default branch ref exists immediately (avoids Git 409 on the first push).

3

Settle

Save the repo pointer, bump the workspace generation fence, refresh global labels, and optionally carry staged buffers into the new workspace.
